OpenClaw新版本拆解：记忆系统和浏览器接力怎么做的

发表于 2026-11-28 分类于 AI 阅读次数： 本文字数： 2.4k 阅读时长 ≈ 2 分钟
OpenClaw 发布 2026.11.10（7671 个 PR），推基于本地 Markdown 与 Git 检查点的 Knowledge 记忆系统、支持冲突并列的 Deep Research 及浏览器标签页接力，补齐可回滚与人机交接底座。

Hello，我是飞飞。

记忆越用越歪、长调研跑一半断线、自动化流程卡在扫码框。这三件事，几乎是所有开源智能体从玩具走向干活工具时必撞的三堵墙。

尤其是长期记忆。刚给智能体接上记忆库时，前两天还觉得它真懂你，过了一周就开始在旧项目里胡说八道，甚至把一次临时的报错猜测当成永久事实写进了库里。更头疼的是，这种污染一旦混进向量库，你连它哪天写歪的、哪条把后续回答带偏了都查不出来。

OpenClaw 刚刚发布的 2026.11.10 大版本，官方贴出来的数据是 7,671 个合并请求、349 位贡献者。

我还没来得及把本地环境升上去实测，但对照发布说明顺着底层拆了一遍，发现它这次最值得看的，恰好是专门挑这三堵墙补起的工程底座：Knowledge 记忆系统、聊天内 Deep Research 和 Browser handoff 浏览器接力。

其中最下功夫的，是把长期记忆从黑盒里拽出来的那套设计。

记忆系统为什么敢用起来

做过个人知识库的人都知道，给大模型加记忆，存进去从来都不难，难的是你敢不敢让它自己改、自己用。

OpenClaw 这次内置了一个叫 Knowledge 的全新记忆插件。在配置里把记忆槽位切换成 knowledge 就能热生效，不需要重启网关，也不会动到原有的旧记忆数据。

它的第一层取舍，就落在了数据底座上。

这套系统没有把记忆藏进看不见的数据库，而是直接落成了一套本地链接化的 Markdown 文件库，专门按人物、组织、项目、关键决策和上下文片段建档。同时还配了一个只读的控制台浏览器按项目时间线翻看，背后挂着定时记录员，按计划自动把聊天对话、Granola 会议纪要和日常工作日志吸收归档进来。

我自己拿 Obsidian 当唯一真实数据源搭个人 AI Brain 时，最深的一个体会就是：向量库检索当然快，可一旦召回结果开始跑偏，你面对的是一堆看不懂的浮点数，连从哪条开始排查都无从下手。只有人能直接双击打开、一眼看懂的纯文本，才谈得上长期可维护。

但光有纯文本还不够，纯文本写乱了照样头疼。OpenClaw 围绕它加了两道在同类工具里很少见的工程锁。

第一道是本地 Git 检查点。每一次记忆的修订、合并和撤回都有版本快照。哪天定时记录员把一条垃圾信息写进了项目档案，你不需要去数据库里大海捞针，像回滚代码一样一键退回上一个干净状态就行。

第二道叫 Shadow Mode，说人话就是影子试跑模式。

你可能会问：先不把记忆喂给模型，那影子模式不就等于白跑一趟？恰恰相反。开启之后，后台照样按真实对话去算每条记忆的匹配分数，只是把原本直接塞进提示词的片段拦在门外，列出一张带分数的清单让你先审一遍。

这就好比给智能体装了一间试音室。哪条三个月前的过时结论被高分捞出来了，你在放行进正式对话前一眼就能揪出来删掉，不用等它胡说八道一通之后再事后救火。

把可回滚和试音室做成默认机制，长期记忆才真正从「碰运气」变成了「敢上生产」。

深度研究不藏矛盾有多难

解决了记忆怎么管，再看长流程调研最容易翻车的第二个环节：怎么保证查出来的东西既不断线、又不瞎编。

现在很多工具做深度调研，最让人抓狂的毛病就是太爱当和事佬。明明网上的两份报告数据互相打架，模型非要自己强行缝合出一句看似圆满的总结，把真正的分歧藏在流畅的废话下面。

OpenClaw 这次上线的聊天内 Deep Research，做了一个很克制的处理：遇到不同来源结论冲突时，系统不会替你和稀泥，而是把两边矛盾的原话直接并排引出来，再单独开一个未决事项区块，把还没查清楚的缺口明明白白标在那里。

这套机制直接用你现有的模型和网页检索工具就能跑，也支持按需接入 Google 的托管研究引擎。

更实用的是它的断线续跑能力。发起一次深度研究后，哪怕你直接关掉当前聊天窗口，甚至中间网关重启了，符合条件的后台任务依然能接着往下跑，跑完的报告会保留七天供你随时回来翻看。

写深度分析或技术调研最怕资料不够，更怕模型替你把分歧抹平了。保留冲突原话加上断线续跑，至少让你拿回来的是一份能直接核对证据链的底稿，免得对着一段看着顺滑、细究全是缝合痕迹的废话重新翻资料。

浏览器接力补上人机断点

如果说前两项在解决「记不住」和「查不稳」，那第三个更新 Browser handoff（浏览器标签页接力），盯上的就是自动化跑一半卡死的尴尬。

用过全自动浏览器代理的人多半体会过那种无力感：任务本来跑得好好的，突然弹出一个扫码登录框，或者撞上一道图形验证码，自动化脚本瞬间卡死在原地。

想把整个流程彻底交给无头浏览器硬闯，往往得折腾一堆脆弱的登录态注入脚本；可如果全靠自己点，又失去了自动化的意义。

OpenClaw 给出的解法很务实：不追求百分之百脱离人类，而是把自动化浏览器任务和你的本地浏览器打通成一条接力跑道。

需要人工过验证、点确认的环节，直接把当前标签页交接给你本地浏览器处理十秒钟，搞定后再把控制权顺滑交回给后台代理继续往下跑。

把人逼着去写脆弱的登录态注入脚本，不如干脆承认这十秒钟本来就该让人来点。能把交接动作做得足够轻，反而比硬吹全自动更能跑通真实业务。

从玩具到干活的底座之争

回想今年年初 OpenClaw 刚爆火那阵，大家讨论最多的还是九十天揽下二十多万星标、社区又多了多少个能点外卖的技能，紧接着就是数万实例暴露公网、恶意技能包混进官方市场的安全风波，甚至一度引来多家大厂和机构的内部禁用。

走到年底，7,671 个合并请求砸出来的，不再是更多抓眼球的玩具演示，而是本地 Markdown 库、Git 记忆回滚、影子召回评分、研究冲突并列和浏览器接力这一整套枯燥但扎实的基础设施。

哪怕是做个人知识库，平时最值钱的也少见于多接几个模型接口，更多在于先把数据源、版本回滚和召回观测这三道底座垫稳。

决定一个开源智能体能不能留下来干重活的，从来只有这些出错时能兜底的底座。

你现在用开源智能体时，最头疼的是记忆越用越乱，还是自动化跑到一半卡在登录验证上？
