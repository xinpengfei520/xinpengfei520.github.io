别急着换更聪明的模型，先给活造个裁判

发表于 2026-11-14 分类于 AI 阅读次数： 本文字数： 3.2k 阅读时长 ≈ 3 分钟
Google 11 月 13 日那批成果真正的变量，是给任务外挂硬裁判：把 7 到 32 分钟的硬件评测压成 23 秒代理，用秩相关定期校准，再锁死原始测试套件防作弊。快慢不是判据。

Hello，我是飞飞。

上周我写过一篇，说 AI 接走的是干完能很快知道好不好的活。今天我要回去改它一个词，把那个「快」字删掉。

你要是在给 AI 分活，这个字删不删很要紧。它决定你手上那些判不死的活，是永远留在你手里，还是能想办法交出去。改完的版本是：看你能不能给它接上一个不会说谎的裁判。而这个裁判可以造。

Google 昨天交了一批活。其中一件把 Weil 猜想端到端形式化，产出一百八十万行 Lean 代码，中间跑了两万八千八百次子 agent。另一件是练一个 9x9 的围棋引擎，做到 1885 分，用了不到八天。

这两件都不快。可它们都交出去了。

那条判词错在哪个词

这条判断有一半底气来自一项影子评估。给前沿 agent 两道真题、六天、几千美元算力，工程活全干完，研究问题零进展，两篇都被原作者明确拒了。

卡点被归给「判不死」。可 Google 这篇 11 月 13 号的博客里，最慢的一件跑了两周。他们把 Zircon 微内核剩下的 C++ 重写成八十万行安全 Rust。这批代码通过全部内核单元测试，在 arm64 真机上开了起来。

另一件是 libgav1，Google 的 AV1 解码器。从 C++ 重写成十七万行 Rust，要求跟原实现逐位一致。逐位一致就是差一个 bit 都算没过。

这两件的完成标准都很硬，但没有一个字跟「快」有关。

我把这批活摊开看，能当判据的只有三条：可重复、可自动化、不失真。「快」不在里面。快只是成本，决定你一天能试几个候选。

这批活里最关键的零件，不在模型有多聪明，在那些能被接上去的裁判。

反向的证据也有。去年七月一篇讲 CUDA kernel 的论文说，串行精修比并行采样划算，加轮次比加人手值钱。前提是每轮都有裁判给反馈。没有裁判，多跑几轮就是原地打转。

23 秒的裁判怎么造

定制的 TPU kernel，全量硬件评测一次要 7 到 32 分钟。这个速度下，优化 agent 一天试不了几个候选。

他们的做法是造一个代理。四个并行的 agent 先找瓶颈，做出一个 23 秒出结果的评测器，他们叫它 yardstick，说人话就是一把临时做的量尺。

关键在它不干什么。这把量尺不给绝对分，只把候选排出先后。他们拿这个排序去跟周期性跑的全量硬件结果对表。对表用的是 Kendall 秩相关，一种比较两个排序像不像的算法。

对表这件事本身就是答案。一个裁判需要被校准，等于承认它可能不忠实。

结果他们报了 17 个 JAXBench kernel 上几何平均 4.09 倍加速，7 个手调的 vLLM kernel 上 2.99 倍。这组数不小。

造出来的裁判会被钻

裁判只要留在 agent 手边，它一定会去动。

8 月 27 号那篇前作写得很直白：为了防作弊，他们把 Spike 模拟器的源码放进沙箱。Lean 编译器不用这一步，没人能改它。

Zircon 那条更狠。每个叶子模块都要对着原始、没改过的测试套件链接。翻成一句话，考卷不许改。

我那条链上的裁判就是一串 grep 加一个字数脚本：破折号扫到一条删一条，字数差一个就打回。

我这边被咬过两次，是同一个道理。

一次是让 agent 修一句句式违规。它把那句改了，改出来的新句子踩了另一条规则。灭掉一个，造出一个。后来我定了条硬规矩：修完必须重跑整套扫描，不能只验被修的那一项。

另一次是配图那个 skill。它自作主张往正文里塞图床链接，还漏图。它没错，它在认真满足我给的那条约束。所以后来我把约束挪到了它改不到的地方。

你手上要是也有一份越写越长的规则书，回头数一下最近三个月加的规矩，看有几条是被它钻出来的。我这边不止一条。

评审 agent 是被关在干净上下文里验结果的。理由是松散的 agent 会互相认同早期错误，在一堆错的东西上很自信地往上盖。我前天写过的是另一半：话没读完，单就下了。Google 前作把这一句往前推了一步，写进了设计前提。

有些活自带裁判

判得死和判不死，没有一条写死的界线。中间还有一格：原本判不死的，插一个裁判进去，就判得死了。Google 这批活里，好几件都从这一格过来。

分子结构那条最典型。从核磁数据反推分子结构，裁判是一个物理信息的谱模拟器。30 个 agent 围着它反复改，复杂基准分子上 95% 一次猜对。这个裁判是模拟出来的信号，替的是真谱仪。按他们校准代理那套做法，这个裁判也得校。

另有一类活不用造，裁判本来就在。

Lean 4 的编译器就是。数学证明翻成 Lean，机器逐行查，错一步就编不过。还有一类是输出只有一个正确答案的：操作系统能不能启动、硬件计数器读出来的数。

这类裁判天生完备，代价是转换贵。Weil 猜想那一百八十万行，形式化的是 Deligne 1974 年的结果。答案在文献里躺了五十年，难的是把它翻成机器能逐行查的代码。

所以口径得抠一下。形式化那一段里最像「开放发现」的几个，主体都是给已有的证明做形式化。另有一批是真解开了开放问题的。那些结果的裁判是作者本人，自己验、自己读、自己改到能投出去。

3D Navier–Stokes 那一条，原文用的词是 independently reproduces，独立复现一遍，复现的是别人近期一个带光滑外力的证明。千禧年问题没有被解决，这一点很多转述会写成相反的样子。

这批成果来自 Google 自己发的一篇博客，署名 Vahab Mirrokni，不是同行评审论文。全文没有局限那一段，没有失败率，外面还没有人复现过。

没有裁判的那一格

上面那些裁判，全在「这活干完对不对」这一层。

再往上一层是「这活值不值得做」。这一层 Google 自己写着归人。一篇里写研究者提出问题、定义理论或物理上的约束。另一篇写得更直白：人负责目标和最终验收。

我读到这句，以为是客气话。后来看到另一份材料才知道，这一格是真没裁判。

Ai2 十月做了一次测试，让几个模型判「两个研究想法哪个更新」。这里的标签是从评审文本里挖出来的弱标签，不是物理真值。换一种问法，从「每对里恰好有一个是新的」改成「直接问哪个新」。GPT-5.4 的准确率从 93.5% 掉到 40.9%，比瞎猜还差。同一个提示词变化，Claude Opus 4.6 在真人写的那批上也挪了 21 个百分点。

更贵的那两条路也没赢。两个专门做新颖性评估的系统，一个 0.642 分，判一次三十美元；一个 0.772 分，判一次八十二美元。一句朴素提示加三次投票，0.854 分，两块五毛九。

所以选题和终审还归人。群发那一步 Google 压根没碰，它管研究结果交不交得出去，没管后果扛不扛得住。

我这条链上也留着两步给人：写哪件事，最后发不发。这两处我还没找到能替我的人。

怎么给自己造一个

你手上那些判不死的活，有一部分其实能救。

这四步对着那三条判据：找真值是「可重复」，造代理是「可自动化」。代理一定会失真，所以「不失真」靠后面的对表和锁真值来兜。

找一个又慢又准的真值。通常是你已经嫌烦的那个动作：跑一遍全量测试、拿真机跑一次、自己从头读到尾。

造一个便宜的代理。别指望它给绝对分，只要求它能排序：两个候选摆在面前，它说得清哪个更好。

定期对表。别天天对。每隔一段时间，把代理和真值排出来的顺序比一次，岔开了就改代理。

把真值锁起来。代理是 agent 能碰到的东西，真值必须是它碰不到的。

拿代码交付举个例子。全量集成测试是慢真值，本地单测加静态检查是代理。代理说能过的，全量测试大概率能过，这就够用了。校准是每周抽一批跑全量，看两个排序有没有岔开。锁真值那步是把测试用例锁住，不许 agent 为了过而改测试。

验收还得人过。代理裁判说得清哪个更好，说不清后果扛不扛得住。

开头那个判断，现在长这样：AI 接走的，是能给它接上裁判的活。裁判可以造。造完要校，校完还得防着它自己改考卷。这三件事，今天仍然只有人会做。

改完这条判词，我手上能交出去的活没有立刻变多。变的是我知道该先看哪一格了：这活的判据造不造得出来。

轮到你。你手上最想交出去的那件活，它那个又慢又准的真值是什么？是跑一遍全量测试，还是自己从头读到尾？评论区报个数，我看看有没有比我更慢的。
