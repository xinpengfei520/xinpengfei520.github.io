五个坑我认得四个，agent 那六天全踩了

发表于 2026-07-30 更新于 2026-07-31 分类于 观点 阅读次数： 本文字数： 2.9k 阅读时长 ≈ 3 分钟
一项影子评估让前沿 agent 接手两篇未发表 NeurIPS 论文的核心研究问题，给它六天和数千美元算力。工程活全干完且不需要人帮忙，研究问题零进展，两篇都被原作者明确拒稿。论文归纳出五个失败模式，其中四个我在自己那条流水线上都被咬过，而五条里至少三条的共同根因是同一个：那个问题没有一条机器能判死的线。

哈喽，我是飞飞。

先说一件让我坐直了的事。

有人给前沿 agent 出了两道真题，是两篇还没发表的 NeurIPS 论文的核心研究问题。给它六天时间、数千美元算力，让它自己去答。

六天后，全部工程活它都干完了，而且没要人帮一把手。

然后两篇都被论文原作者明确拒了。

我得先撇清一件事。「agent 能干活但拍板得我自己来」这句话，我在这个号上说过不止一次。前天那篇讲流水线假线的，还说了一遍。所以这篇要是又落到那儿，就是车轱辘话。

这次不一样的地方在于：我以前那句话是个立场，凭的是体感。这篇论文给的是诊断，它把 agent 在这件事上具体败在哪，拆成了五个能点名的地方。

而那五个地方里，我认得四个。

六天干完，一步没答上

先把原文摆清楚。

这篇是 arXiv 2607.27191，7 月 24 日的，17 页。作者名单挺重，里面有 Sayash Kapoor 和 Arvind Narayanan，就是写 AI Snake Oil 那两位，还有 Helen Toner。

它们管这套方法叫影子评估。做法是让 agent 去接一篇高质量未发表论文的核心研究问题，产出交给论文原作者本人打分。作者说这套做法卡在「狭窄可验证任务」和「盲审投稿」中间，是另开的一条路。

结果分成两半，反差就在这儿。

工程那一半，原文写的是全部完成，而且不需要人类帮助。数据处理、跑实验、写代码，六天里它自己走完了。

研究那一半，原文写的是没能取得实质性进展。

两篇论文的原作者给出的评价，英文原话是 unambiguously rejected，明确拒绝，没有留余地。

得说清一件事，这只有两个案例，作者自己也把标题写成「早期证据」。两篇论文推不出「AI 永远做不了研究」这种结论，我不打算替它把话说大。 论文也没点名用的是哪个模型，我照样不猜。

我以前只有一句我不放心

论文归纳的五个失败模式，我按原文列一下：

  • 对可发表研究标准认识不足
  • 对研究设计缺陷反应不创新
  • 从死胡同回溯效率低
  • 资源意识欠缺
  • 指令漂移

我读下来的头一个反应是尴尬。本来以为会读出「果然如此」那种痛快，结果没有。

因为这五条里有四条，我在自己那条流水线上都被咬过。我给它们打过补丁，那些补丁现在还在 skill 里跑着。

但我一直以为那是我自己攒的经验。读完这篇我才反应过来，那些坑是一类系统性的缺陷，早被人写进论文里了。我只是在自己那个小作坊里，一个人把它们重新发现了一遍。

下面挨个对。

头两条说的是它没尺子

头一个失败模式是不知道什么叫「够得上发表」。

我这边的对应物很直接。说真的，agent 写完一篇稿子，它自己觉得挺好。它没有那把尺子。所以我在流水线里塞了一个专门打分的环节，按刘润那套六个维度打，满分一百。最近几篇落在八十五到八十九之间，低于八十就派回去做一轮定点重改。

那把尺子是我硬装上去的。它自己长不出来。

紧接着那个更贴我。原文说的是遇到研究设计有毛病时，它的反应不够创新。

翻译到我这儿就是：稿子字数没到下限，它的反应是注水。回头问一句「要不要去补点真东西」，它想不到。规则给了一个约束，它的动作就是想办法把这个约束满足掉。至于这个约束本身有没有把问题设计歪，它不会去碰。

还有一次更典型。我让它修一个句式违规，它把那句改了，改出来的新句子踩了另一条规则。灭掉一个，造出一个。这件事后来被我写成了硬规矩：修完必须重新过一遍完整的扫描，不能只验被修的那一项。

说白了这两条是同一件事。它努力得很，卡的地方在于手里没有一把能判「这样行不行」的尺子。没有尺子，它只能对着你给的那条约束死磕。

中间那条我等过四十秒

从死胡同回溯效率低，这一条我有过很具体的画面。

四月我用 Ollama 拉了 gemma4 的 e4b 接上 Claude Code。模型生成到一半停住了，停完把前面写过的内容又吐了一遍。我盯着屏幕等，等了四十秒，才反应过来它在原地打转。

它不知道自己进了死胡同。

但这一条我得给它说句公道话，因为我见过反例。之前实测 MiMo Code，让它写一个解析 Markdown 头部的小工具。它自己写了测试，跑出来五个用例三过两败。然后它读 TAP 的报错，自己诊断出是正则抢先匹配，一次修改把正则收紧，重跑五过零败。

同一个能力，在有测试可判死的地方它回溯得干净利落，在没东西判死的地方它原地转四十秒。 这个对比我记了很久，今天算是找到了它的名字。

它不会心疼钱

资源意识欠缺，这条我是用钱换来的认识。

我跟你讲，它是真的不会心疼。我会。所以我调用 Opus 之前会在心里过一遍秤，杂活手动切便宜模型。我把缓存命中率从三成调到七成三，账单从一百零六美元压到三十三美元。我把 CLAUDE.md 从 12KB 砍到 4KB，因为那份文件每一行每一轮都当前缀重发一次。

多智能体那套跑法烧的 token 是普通对话的十五倍，这个数我引过好几次。

这些动作没有一个是 agent 自己想出来的。账单疼的是我，所以省钱的活也只能我来干。

最后那条我上周才犯

最后那个失败模式叫指令漂移。就是给了它一份指令，跑着跑着它偏了。

我这边的老账很多。配图那个 skill 一开始没把规则写死，agent 就自作主张把图床链接塞进正文，还漏图。防 AI 味的规则它也会绕过去。这些后来都靠把该确定的步骤抠死解决了。

但真正让我不太好意思的是上周那件事。

前天那篇文章讲的是，我拿「虚假连线」这个概念去审了一遍自己那条流水线。结果发现文档里画着两个环节串行执行，可实际跑的时候，它们早就并行了。图和现实分了家，而且错的是图。

论文说的是 agent 会偏离它的指令。而我那次的漂移更难看一点：是我自己写的文档和我自己的执行分了家，人和 agent 一起漂，还漂了几十篇才被我抓到。

它至少还是照着一份写死的指令在漂。我那份指令本身早就不作数了。

判不死的那条线

把五条摊在一起看，我觉得至少三条底下是同一个根。

工程活能判死。测试过没过、代码跑不跑、数据处理完没完，都有一条机器能自己验的线。所以它六天全干完了，不需要人帮忙。

研究问题判不死。这个方向值不值得追、这个结果够不够格发出去、这个设计有没有从一开始就歪。没有哪个函数能对这些返回真或假。

那六天真正卡住它的，不在它不够聪明，在那个问题没有一条机器能判死的线。

这也解释了为什么它在 MiMo 那个小工具上回溯得那么漂亮，在死胡同里却能转四十秒。它的能力只有一套。区别在有的地方有线，有的地方没有。

你那条线上哪一步判不死

所以这篇给你的东西挺具体。

如果你手上也有一条派 agent 干活的流程，今天可以做一件事。把每一步拎出来，问一句这一步的完成标准，机器能不能自己判。

能判的，比如格式对不对、测试过不过、字数够不够、链接通不通，尽管交出去，它干得比你快也比你稳。

判不死的，比如这个选题值不值得写、这个判断敢不敢下、这篇够不够格发出去。那几步就是你今天还得坐在那儿的理由。

我自己这条线上判不死的只有两处：选题拍板，和最后那句能不能发。中间那八个阶段，从四月搭起来就一直是交出去的，到现在没想收回来。

不过读完这篇我加了一件事。以前我只是「觉得」那两处得我来，现在我知道它具体会怎么砸。知道它会在哪儿摔，比笼统地不放心，让我敢交出去的东西多得多。

最后想问问你：你那条流程里，有没有哪一步你一直亲自盯着，但仔细想想它的完成标准其实是能写成代码判的？说说是哪一步，我挺好奇大家都在手动守什么。
