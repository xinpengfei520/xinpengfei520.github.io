把 28 层权重循环跑两轮：智谱 GLM-5.4 凭什么用 Loop 架构硬刚 2-3T 级模型？

发表于 2026-11-23 更新于 2026-11-24 分类于 AI探索 阅读次数： 本文字数： 2.7k 阅读时长 ≈ 2 分钟
智谱发布全新旗舰模型GLM-5.4，首次在工业级基座落地Loop Transformer架构，通过28层权重循环执行两轮换取2至3T级推理智能，并全量上线面向开发者的泛Coding生态。

Hello，我是飞飞。

如果你平时经常在代码编辑器里挂着各种 AI 助手，今天大概率会被一条新更新刷屏。

智谱正式上线了他们的全新旗舰模型 GLM-5.4，并且直接在面向开发者的订阅体系里全量开放。这次大家最关注的，是他们在模型底层骨架上动的那把大手术：没有去死磕常规的参数规模翻倍，而是第一次在工业级旗舰基座里，把传统的单向流水线换成了 Loop Transformer 架构。

他们让模型内部特定的 28 层权重，在推理时循环执行两轮。

按照官方公布的数据，在参数量完全不膨胀、静态显存占用保持不变的前提下，通过增加单次推理的计算深度，模型在复杂逻辑与代码任务上的智能表现，直接逼近了传统 2 到 3 万亿参数的超大底座。

这在如今动辄拼算力规模、拼集群卡数的技术大环境里，算得上一条极具辨识度的突围路线。

不再盲目给模型增肥

过去这两年，整个行业几乎被一套默认的升级惯性推着走：想让模型变聪明，最粗暴的办法就是堆参数。

从几十 B 一路飙升到几百 B，再到由众多专家网络拼起来的 MoE 庞然大物。参数量越庞大，为了把模型完整装进显卡集群，所需要的显存和卡间通信开销就越夸张。

对于真正做业务落地和工具开发的团队来说，这种虚胖正变得越来越难以承受。

很多大模型在实验室里跑得风生水起，可一旦部署上线，高昂的租用成本和缓慢的吞吐量，立刻把很多原本很有想象力的应用场景给卡死了。单纯依靠物理参数扩张的边际效益，肉眼可见地在收窄。

智谱这次选择交出的答卷，本质上是在向深度要智能，而不是向体积要智能。

既然无节制地增加网络层数会把显存吃崩，那能不能把已经设计精良的中间层拿来反复使用？这就是他们激进探索循环深度的现实考量。

同一批权重的两次遍历

在传统的 Transformer 架构里，信息的流动是严格单向的。

输入的标记从第 1 层逐级向上传递，流过几十层网络，最终在网络顶层输出下一个词的预测分布。每一层网络只能对经过的数据看一眼，哪怕中间推演遇到模糊的信息，也没有机会回头重构。

Loop Transformer 打破了这个单行道规则。

在 GLM-5.4 的设计里，中间特定的 28 层网络被构造成了一个可以循环复用的计算环路。当信息流完整穿过这 28 层之后，并没有直接被送往输出端，而是带着初步提炼出的上下文状态，重新注入这组权重，再次深度遍历一遍。

同一个网络权重，跑两遍真的能让模型更聪明吗？

答案藏在表征的渐进细化里。第一遍遍历时，网络往往完成的是宏观语境抓取和粗粒度概念对齐；而带着这些高阶上下文跑第二遍时，注意力机制就能够在更精确的约束下，对复杂的代码符号、变量作用域和长依赖逻辑做二次校准。

这很像人类工程师读复杂代码时的真实思维过程。遇到几千行的陌生模块，很少有人看一遍就能看懂全部调用链路，通常都是先快速扫出整体框架，带着框架的先验记忆再精读一遍具体的实现细节。

通过复用静态权重，模型的有效计算深度直接翻倍，让有限的参数释放出了极高密度的推演潜力。

延迟与缓存的工程平衡

任何架构上的创新，在物理现实里都要付出对应的代价。

循环执行最显而易见的软肋就是推理时延。如果每个词的生成都要把中间层硬跑两遍，理论上的纯计算时间直接翻了一倍，很多对响应速度极度敏感的实时交互就会严重受挫。

为了不让循环架构在实际部署中沦为不可用的技术玩具，智谱在工程实现上做了相当克制的取舍。

核心的防线是门控机制与动态稀疏策略。并不是所有简单的字词预测都需要拉满两轮循环，模型内部内置了置信度感知模块，在面对常规语言组织和语法填充时，能够提前跳出循环快速放行；只有在进入复杂的逻辑判断、长算法推导或多层括号匹配等高熵区域时，才会真正激活完整的二次循环计算。

与此同时，循环机制必然伴随着键值缓存的频繁读写与显存激增。他们对跨轮次的状态传递做了高度优化的稀疏复用，确保中间激活不会无上限地堆积在显存池里。

正是靠着这套自适应调度，GLM-5.4 才得以在主流推理卡上跑出兼顾吞吐与深度的商用表现。

从写代码到泛Coding

在架构突围之外，智谱对 GLM-5.4 赋予的定位也耐人寻味。他们不再把这个模型局限在传统的辅助编程工具箱里，而是打出了泛 Coding 的概念。

以往我们谈论代码模型，脑子里想到的场景通常非常单一：在 VS Code 里补齐一行代码、根据接口文档写一段增删改查、或者把报错日志贴进去问怎么修。

这些当然很重要，但它们仍然被严格圈定在传统软件工程的窄门里。

智谱展示的泛 Coding 逻辑，是把代码直接当成了多维数字内容生产的统一中介语言。

在内测与官方演示里，这个模型不仅能写前后端业务，还能直接用代码驱动复杂的矢量图形渲染、用前端脚本编排音乐动画，甚至结合专业三维引擎的脚本接口，端到端生成可交互的 3D 场景与机械控制代码。

再加上这次基座原生补齐的视觉能力，支持同时看懂参考界面截图、报错截屏与百万级上下文的完整代码仓库，模型与真实工作环境的连接面一下子被拓宽了。

为什么代码是最好的中介

为什么大模型跨界做复杂内容创作，反而要把代码作为支点？

做过一线开发的人都很清楚，大模型如果直接生成自然语言长文本，往往极度不可控，非常容易写出看似逻辑通畅、实则空洞无物的虚假段落。

因为自然语言缺少刚性的物理约束，容错空间太大，模型容易在幻觉里越滑越远。

但代码完全不同。代码是人类创造出来的最精确、最严谨的形式化符号系统。

一段代码写出来，究竟对不对、能不能运行、布局有没有错位、三维空间坐标有没有碰撞，根本不需要靠人的主观感觉去猜。只要把代码丢进对应的解释器或编译器里，执行引擎会在几毫秒内给出极其冷酷且确定的反馈。

把代码当成生成中介，实际上是给大模型的概率输出套上了一具确定性的外骨骼。

大模型负责理解意图、构思全局架构，而具体的几何计算、渲染流水线和物理动力学运算，全部交给经过几十年工程检验的成熟代码引擎去严格执行。这种组合，远比纯文本直接端到端臆想画面要可靠得多。

开发者工具箱里的新变量

对于我们平时把各类 Coding Agent 当成主力副驾的工程师来说，GLM-5.4 的出现提供了一个非常具体的选型参考。

如果你日常面对的只是轻量的脚本补全或简单的函数改写，常规的轻量小模型依然具备速度上的绝对优势，不必杀鸡用牛刀。

但当你需要处理跨多个模块的深层架构重构、需要让智能体结合视觉界面原型直接写出高还原度的全栈组件、或者需要编写算法密集型的推演逻辑时，这种依靠循环计算深度来保障逻辑严密性的基座，展现出来的韧性会显著不同。

当全行业对参数堆叠的狂热逐渐平息，如何用更精巧的结构在有限的硅基资源里榨出更高密度的智能，正在成为下一阶段的核心看点。

这次智谱在 Loop 架构上的坚决下注，或许正是给这场大模型工程进化，拉开了一个务实而硬核的序幕。
