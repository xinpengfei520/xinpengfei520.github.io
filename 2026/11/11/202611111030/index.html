59,417 对 1,421：MCP 为什么多读 42 倍

发表于 2026-11-11 更新于 2026-11-12 分类于 工具 阅读次数： 本文字数： 3.3k 阅读时长 ≈ 3 分钟
同一件查版本查问题单的活，命令行花 1,421 个输入 token，默认 46 个工具的 MCP 花 59,417 个，差 42 倍；我本机 4 个 MCP、100 个工具占 4.7 万 token，工具说明书是每轮都重付的租金。

Hello，我是飞飞。

先说个我刚看到的数。同一个任务，查 cli/cli 的最新版本，再翻三条最新的 bug。用命令行做，Claude Sonnet 5.5 一共读了 1,421 个输入 token，花 0.0075 美元。挂一个默认配置的 GitHub MCP 做，读 59,417 个，花 0.1274 美元。两个都答对了。

MCP 是让 AI 能调外部工具的插头标准，Claude Code、Cursor 里都能挂。挂上一个，对方服务器上的一整套工具就进了你的上下文。说明书也跟着。token 是模型读写和计费的最小单位，账单按它算。

MCP 本身是好东西。它把各家服务接进模型这件事标准化了。省掉了一大堆自己写适配的活。问题出在计费方式上。

输入 token 差 42 倍，成本差 17 倍。贵出来的部分跟模型聪明不聪明没关系。每一个请求里，46 个工具的说明书都会被重新发一遍。工具返回的整页结果，也会被重新放回上下文。

这笔钱不出现在任何一张单独的发票上，所以你很难注意到。但只要你挂过 MCP，你每开一次对话就在付一次。

42 倍差在哪

这是 OpenRouter 在 10 月 20 日自己跑的对照。同一个任务、同一套模型，只换接入方式。每种配置跑三次，取中位数。Sonnet 5.5 上的结果是这样：

接入方式 输入 token 每任务成本
命令行 1,421 0.0075 美元
一个 skill 3,315 0.0118 美元
MCP，只开 2 个工具 23,228 0.0552 美元
MCP，默认 46 个工具 59,417 0.1274 美元
MCP，91 个工具全开 101,351 0.2113 美元

换个算法更直观。默认 MCP 每跑一千次任务 127 美元，命令行 7.5 美元。

同一套配置换模型也会变。同一个 46 工具的 MCP，GPT-6 Luna 要 116,282 个 token，命令行只要 627 个；Gemini 3.8 Flash 是 35,409 对 5,292。倍数差得很远，方向一致。

任务本身很小，查一个版本号加三条问题单。连一次完整的活都算不上。任务越小，固定开销占比越大。这解释了 42 倍为什么看着吓人。也提醒你，别把它直接套到一整天的开发上。

反过来说，任务越大，真正读代码写代码的时间越长。这份说明书的占比就越小。它是一笔固定成本，越小的活越显得贵。

多出来的第一块，是那 46 个工具的定义。原文算过，它们每请求加 19,436 个 prompt token，也就是提示词里多占的这部分上下文。换谁来跑，都得先把这份说明书吃进去。这还只是说明书，真正的结果还没回来。

为什么每轮都要重发？模型调工具，每次请求都是独立的一次。没有一个长会话，让它一直握着那套工具。它要在第二次调用时还认得这 46 个工具。你就得把说明书再递一遍。这跟我们装软件不一样，装一次就一直在。

46 个已经这样，91 个全开更夸张。光加载就比 46 个多花约 42,000 个 token。延迟加载时，91 个只比 46 个多 1,281。真正贵的是把说明书摆出来这件事本身。

返回吃掉了三成

查一次版本发布的返回有多大？42,182 个字符。其中 87% 在描述 22 个下载文件。折合约 20,400 token，比 46 个工具定义加起来还多。

20,400 放在 59,417 的总输入里，占三分之一。一次返回就是这么多。

还有个更夸张的例子。不让模型指定字段，GPT-6 Luna 就会乱要。六次运行，四次一口气要了 100 条问题单全文。返回 281,963 个字符。它读完了。但每一轮，都要带着这坨东西继续。

工具调用不是一次就结束。模型看完结果要再说一句。这一句的上下文里，又带着刚才那一整页。来回三轮，同一份返回就被算三次。

你在 Claude Code 里让它查个问题单、跑个命令。背后可能已经来回三四轮。每一轮都在为同一份工具清单付费。

所以只砍工具数量，效果有限。只开 2 个工具时，首个请求从 19,487 降到 1,406。可整任务还是 23,228 个 token，因为结果还在。

把结果截到 4,000 字符，才降到 5,357，而且所有运行仍然答对。原文提醒了一句，这次能成是因为需要的字段恰好排在前面。换个返回结构，未必。

还有一招几乎不要成本：要字段。查问题单的那个工具，只要编号、标题和创建时间，返回从 8,336 个字符降到 714。

缓存救不了哪一半

这组对照算的是输入 token 总量。真实账单里，工具定义每轮都一模一样，有机会命中 prompt 缓存。单价会低一截。

我自己的缓存命中率从三成调到七成三。一条 API 流水线的月账单，从 106 美元压到 33 美元。缓存是真金白银。

缓存只认一模一样的前缀。工具的顺序调一下、描述改一个字，命中就断了。

但它救不了每次都在变的结果。那些 token 依然占着的上下文位置，它也救不了。窗口就那么大，说明书和结果先把位置占了。留给你的代码和问题，就少一块。

我让工具查了自己

我让 Claude Code 在我这台机器上跑了一次 /context。它把开口前的家底摊开。MCP 工具那行是 47.1k，比系统工具、记忆文件和 Skills 加起来还多。

项目 占用
系统提示 1.9k
系统工具 20.3k
MCP 工具 47.1k
MCP 服务器说明 406
记忆文件 4.4k
Skills 9.9k
合计 84.1k

说实话，84.1k，我还没打一个字。

MCP 那 47.1k 来自报告里列出的 4 个服务器、100 个工具。其中一个是社区服务，69 个工具，一个服务就占了 34,256 个。我配置里一共 11 个 MCP，当时连上了 9 个。报告只摊开了先加载完的 4 个，所以这 47.1k 只能算下限。

一个 MCP 装进来，往往是因为某个下午要它干一件事。事干完了，工具留在配置里，下次启动照样加载。

84.1k 放在 786k 的窗口里是 11%，看着不疼。可要是 20 万窗口，开口前四成多就没了。工具还是那些工具，占比跟着窗口变。

CLAUDE.md 我砍过，从 12KB 压到 4KB。skill 我也删过，从 50 多个减到 28 个，Skills 那栏从 4.2k 回到 1.2k。MCP 这一栏，是今天这张表里最大的一块。

今天再看，Skills 那栏又回到 9.9k。我全局 skill 目录里躺着 128 个。

还有件事。我那个无人值守入口的启动脚本里有一行 ENABLE_TOOL_SEARCH=false。白纸黑字写着。什么时候加的、为什么关，脚本里没留一个字的注释。

少挂工具就够了吗

不够，但省下来的部分是真的。

只开 2 个工具时，整任务 23,228，还是 CLI 的 16 倍。再砍返回，5,357，差不多是 CLI 的 3.8 倍。

延迟加载不是白捡的，它挑模型。Sonnet 从 59,417 降到 30,334。Haiku 5.5 反过来从 99,319 涨到 154,623。参数格式不对，重试把省的全吃回去。GPT-6 Luna 搜了三到六次，有一次干脆没调工具就放弃。

所以顺序不能反。先把返回砍到够用，再砍工具数量。再往后，才是延迟加载。

我会按什么顺序动刀

先看手上有没有命令行。有，而且 agent 能跑命令，就让 agent 跑命令行。1,421 个 token，是这套对照里最便宜的。

命令行不熟、或者用法每次都不一样，配一个 skill。3,315 个 token，换来的是一套稳定的步骤。

没有命令行，或者要服务端鉴权，才上 MCP。上之前只开当下要用的工具，别把 69 个全挂上。

返回一律按需取字段。这条最便宜，也最容易被忘。

工具定义超过一万 token 或者十个工具，再考虑延迟加载。留三到五个最常用的常驻。

MCP 没必要全卸。没有命令行的地方，它仍是正解。要服务端鉴权、要统一管权限，也是。原文的建议同样分场景，没有一刀切。

想自己查，在 Claude Code 里敲 /context，看 MCP tools 那一行。再敲 claude mcp list，看哪些服务器真的连着。不用的先在 /mcp 里关掉，比改配置文件快。

这一套我还没在自己的机器上做完。如果你也想动，先挑工具最多的那个服务收窄。再跑一次 /context，对着看降了多少。

绕回开头那 42 倍。它不是模型的价钱，是每次请求都替你重读一遍说明书的租金。模型换得再便宜，这笔租金照收。

你打开 /context 看一眼，MCP 那栏是多少？如果比我这个 47.1k 还高，先把工具数报给我。我想知道，是不是只有我把工具箱背在身上出门。
