造Claude的人怎么写代码？Anthropic平台总监揭秘

发表于 2026-11-26 分类于 技术探索 阅读次数： 本文字数： 3.1k 阅读时长 ≈ 3 分钟
Anthropic 平台工程总监 Katelyn Lesse 在深度专访中揭秘：团队工程师有 80% 的智能体代码根本无人逐行肉眼审阅，开工时几乎无人精通 Rust，传统手撕算法面试已被彻底废除。

Hello，我是飞飞。

如果你平时天天用 AI 帮自己写代码，你心里多半有过一个强烈的好奇：那些亲手打造出这些前沿模型的顶尖工程师们，自己平时在公司里到底是怎么写代码的？

他们是真的已经彻底甩手给智能体，还是依然坐在屏幕前，像老牌工匠一样逐行紧盯每一次代码提交？

著名技术访谈节目《The Pragmatic Engineer》刚刚放出了一期长达两小时的重磅专访。受访嘉宾是 Anthropic 平台工程总监 Katelyn Lesse，她统领着整个 Claude API、Claude Code 和客户端基础设施的工程团队。

在这场毫无保留的技术对话里，她撕开了无数关于大模型与大厂研发的温情滤镜，甩出了一串让传统程序员甚至资深架构师都瞠目结舌的事实。

其中最扎心的一句话是：在他们团队用智能体完成的大规模工程重构里，工程师们有大约 80% 的代码，从头到尾根本没有人去逐行阅读过。

当传统软件工程里最神圣的 Code Review 机制轰然瓦解，我们到底该如何定义这个时代的优秀工程师？

八成代码竟然无人肉审阅

在过去几十年的软件工程教科书里，人工代码审查几乎被奉为保证系统质量的最高信条。

一个合格的工程师，必须睁大眼睛盯着每一个合并请求的每行改动。看命名规不规范、边界条件漏没漏。任何未经人眼严格校验的代码被推上生产，在传统团队里都会被视为事故隐患。

但 Katelyn Lesse 却公开坦白：面对数以万计由 Claude 智能体生成的代码，人肉逐行阅读代码的旧习惯已经被彻底击穿了。

智能体写代码的速度实在太快了。它可以在几个小时内吐出几千行逻辑完备的实现代码，甚至主动修完所有配套的单元测试。如果人类工程师依然执着于泡上一杯咖啡、在网页端一行行肉眼找茬，人类肉身就会瞬间成为整条流水线上最严重的大血栓。

Anthropic 团队的选择极其冷酷而务实：把人类注意力从漫无边际的样板代码里全面撤离，死守那关键的 20% 承重结构。

他们只在最底层的系统状态机、数据流边界以及核心并发模型上花费人肉心智。至于剩下 80% 的字段映射、格式转换、中间件适配和胶水逻辑，根本没有人去逐行审阅。

敢于甩手的底气，来自于强类型语言本身的严苛约束，以及实时的全量影子流量对比。强类型编译器的借用检查和内存模型，在最前线替人类封死了野指针与数据竞态；而全量流量差分体系，则在终极防线做无死角的行为对齐。

代码不再是用来被人逐字品鉴的散文，代码已经变成了系统流水线上被机器生产、被机器校验的工业构件。

团队没人精通也可以重构

专访中抛出的第二个震撼细节，是关于他们不久前把核心网关用 Rust 彻底重写的内幕。

把承载数万亿 Token 流量的命脉服务从 Python 换到 Rust，在任何大厂都是史诗级战役。传统逻辑里，第一步必然是高薪挖角一批 Rust 老手。

但 Katelyn Lesse 透露的真相让所有人大跌眼镜：在重构项目启动的那天，整个团队里几乎没有一个人真正精通或者长期写过生产级的 Rust 代码。

主力全是一群常年写 Python 的工程师。

如果放在五年前，让一群 Python 程序员去写大规模的高性能 Rust 系统，基本等同于让骑兵去开航母。Rust 繁琐的所有权机制、生命周期标注以及复杂的宏系统，足以把没有经验的团队折磨到项目流产。

但有了 Claude 智能体之后，语法和语言壁垒被生生碾碎了。

人类工程师负责把系统的关键不变量、数据结构形态和测试基准设计得清清楚楚。至于怎么在 Rust 里满足借用检查器的挑剔胃口、怎么选用最恰当的原子操作库、怎么写出零成本抽象的语法糖，绝大部分实现代码全由智能体直接输出。

高级语言到系统级语言的陡峭学习曲线，在智能体面前被抹平了。

这直接给所有开发者敲响了警钟：靠“掌握某门小众冷门语言”来建立技术壁垒的日子，正在加速终结。

传统白板刷题面试正式死亡

正因为团队内部的写代码方式发生了剧变，Anthropic 官方做出了一个极具风向标意义的决定：彻底取消传统的白板手撕算法面试。

过去十几年里，技术招聘体系把刷题推向了高峰。不管应聘什么岗位，面试官都会要求四十分钟内手撕红黑树或反转链表。

Katelyn Lesse 在播客里毫不客气地指出了这套模式的荒唐：他们跟踪发现，那些能在白板上倒背如流把算法题写得滴水不漏的候选人，进入真实的智能体开发环境后，往往表现得极其平庸甚至非常痛苦。

因为在真实的生产环境里，手写二分查找这类微观算法的工作，智能体一秒钟就能写出十种变体，根本不需要人类去苦苦记忆语法模板。

反过来，很多死记硬背算法的高分选手，面对一个模糊复杂的真实工程问题时，既不知道该如何给智能体提供精准的上下文边界，也不会设计自动化评测基准，面对智能体生成的几百行代码更是手足无措。

Anthropic 的技术面试，全面转向了考察候选人如何指挥智能体协同作战。

考你能不能在几十分钟内，利用智能体快速搭建出一套可运行的系统；考你能不能敏锐发现智能体输出代码里的逻辑缺陷；考你能不能设计出滴水不漏的测试护栏，把智能体生成的未知代码稳稳锁在安全区间。

敲键盘的速度与背题的熟练度，正在被系统设计与智能体驾驭力彻底取代。

工程师成为系统护栏建筑师

当写代码这件事情本身被大面积剥离之后，Anthropic 的工程师们平时究竟把时间花在了哪里？

Katelyn Lesse 给出了极其清晰的画像：他们正在从传统的代码实现者，全面转型为系统的护栏建筑师。

工程师们最宝贵的精力，全部被注入到了构建评测基准和验证体系上。

在他们团队里，一个高价值工程师的日常工作，不再花在从头敲业务类上，转而全面琢磨如何为长任务智能体编写严谨的运行时测试沙盒。

如果智能体需要执行长达几个小时的代码重构，人类必须提前给它划定好安全红线：哪些文件允许触碰，哪些核心接口不容修改，在出现什么样的偏离指标时系统必须强制中断并报警。

同时，工程师们把大量时间花在优化上下文和提示词体系上。如何用极其克制、结构化的指引，让智能体在数万行代码的庞大工程里不迷路、不产生上下文漂移。

人类做规则制定者与裁判员，智能体作为不知疲倦的数字工人快速砌砖。

这种分工重塑了整个团队的交付势能。过去需要几十人跨月推进的基础设施改造，如今几个核心工程师带着智能体编队，在几个月内就能干脆利落地交差。

重新定义软件开发的护城河

听完这期近两个小时的深度对话，每一个从业者都无法继续维持过去的鸵鸟心态。

软件开发这个延续了半个多世纪的古老职业，并没有像某些悲观论调预言的那样就此消亡，但它的底层生存法则，已经被彻底重写了。

如果你还沉浸在自己能熟练背出框架 API、能比别人少打两个按键的微小优越感里，时代抛弃你的时候甚至不会提前打一声招呼。

因为在强大的大模型与智能体集群面前，任何关于记忆力、打字手速和语法熟练度的比拼，都成了毫无意义的徒劳。

真正的护城河，已经转移到了对真实业务逻辑的洞察、对复杂系统架构的驾驭，以及构建自动化验证体系的能力上。

造 Claude 的人已经给我们指明了未来的航向。学会放下对每一行具体语法的虚假控制欲，走到系统边缘去搭建坚固的护栏，学会在机器的轰鸣声中做那个冷静的发牌者。

时代把代码生产的权杖交给了机器，而那个能够定义边界、审判真伪的架构大脑，依然牢牢掌握在少数清醒的工程师手中。
