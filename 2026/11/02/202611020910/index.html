12 月起，你算不出自己还能用多少

发表于 2026-11-02 更新于 2026-11-03 分类于 观点 阅读次数： 本文字数： 2.9k 阅读时长 ≈ 3 分钟
OpenAI 12 月起让 ChatGPT 与 Codex 共用额度、按 token 计量，用尽可买 credits；Claude 官方文档早已是同一形状，衡量方式改变后用户将难以预估剩余用量。

Hello，我是飞飞。

OpenAI 在帮助中心写了：从 12 月开始，Plus、Pro、Business 三档的 ChatGPT 和 Codex 共用同一份额度。

我盯着那句话看了很久，因为这套东西我住了大半年。

我用 Claude Pro，主力编程工具是 Claude Code，整条写作流水线都长在上面。Claude 那边的官方文档里，早就写着聊天和编程算同一份额度。所以 OpenAI 这次要上的形状，对我来说已经是日常。

今天想聊的是：搬进这个形状之后，日子会变成什么样，硌人的地方在哪。

它改的是尺子

先把官方那几句摆出来。

OpenAI 的原话是，ChatGPT 和 Codex 的用量「will be measured in tokens」。更高级的模型、更复杂的任务，通常吃掉的额度更多。Instant 聊天不占这份额度。用完三条路：等重置、升档，或者买额度继续用。

注意，官方没说每档给多少 token，也没说具体哪天，只说 December。

不过有一句挺实在。官方写了他们正在「carefully」准备这次切换，为的是避免打断用户的工作流。一家公司会在帮助文档里专门写这句，说明它自己也知道，这次会让人不习惯。

很多人把这次理解成「OpenAI 又收紧了」。我觉得它动的不是上限的高度，是上限的形状。尺子换了，池子也并了。

以前按条数算，你心里有个数：今天还能问几句，还剩几条编程请求。现在按 token 算，同一个问题，你多写两句背景、换个更强的模型、把推理档位调高一档，消耗全都不一样。

你还是能问，只是你估不出来了。

一个池子两种用法

第二件事更容易被忽略：池子并了。

聊天和编程本来是两本账。聊天是低强度高频次，一天问几十个短问题；编程是高强度突发，一个 agent 任务跑四十分钟，一口气烧掉一大块。

以前它们各花各的，互不影响。现在一个池子。

官方还留了个口子：Instant 聊天不占这份额度。也就是说，你随手问个天气、查个词、让它改句话，这些不受影响。真正吃额度的是长对话、强模型，以及编程任务。

这个设计的潜台词挺清楚：便宜的用法放开，贵的用法收紧额度。听起来合理，落到你身上就是，你得开始分辨自己刚才那一问算哪一种。

官方写了句安抚的话：大多数用户不会比以前更频繁地等重置。这句我信，它说的是平均。

平均数救不了一个具体场景。

你下午两点让 agent 跑一个重构，它跑了四十分钟，一口气吃掉一大块。晚上九点你想让它帮你看段文案，输入框回你一行重置时间。

没人做错什么，只是两份预算被合并成了一份。

用完可以买

第三条才是这次最该被看见的。

官方措辞是「buy credits to continue using eligible features」，买额度，继续用符合条件的功能。

这句话把订阅制悄悄改了一层。

以前是从月付到上限，到点就停，要么等，要么升档。现在多了一条路：到了上限，花点钱接着干。听着是好事，但它意味着「这个月的额度」不再是硬边界，变成了一条软的建议线。

还有个细节值得抠：官方写的是「符合条件的功能」。哪些算符合条件，文档没展开。所以别把它读成「花钱就能无限用」。

我那边也长这样。Claude 的帮助中心里有一条单独的「买用量包」。

这跟手机流量包有点像，又不太一样。流量超了是限速，你还能慢慢刷；额度超了是直接停，除非你买。一个是降级，一个是断供。

订阅制走到这一步，其实很自然。真正贵的东西跟模型无关，贵在你干活干到一半被打断。

所以那份 credits 卖的其实是「别停」，token 只是它的计价单位。你掏的那笔钱，买的是别被打断。你自己的上下文、你刚跑了一半的那条链路，都在那个「别停」里面。

这套形状我住着

说说我那边的机制，都能在官方文档里查到，不是我的推断。

Claude 的付费计划有两种限制：一个是每 5 小时重置的 session 限额，另一个是一周重置一次的周限额。

5 小时这个窗口的起算方式，我觉得很多人不知道：它从你发第一条消息开始计时，满 5 小时整体重置。它不是固定的钟点窗口，比如「每天 9 点到 14 点」。你今天几点开工，窗口就从几点开始滚。

文档里还有一句原文：你在 claude.ai、Claude Code、Claude Desktop 上的用量，「counts towards the same usage limit」。

一个池子，聊天、编程、桌面端，全算在一起。

用量受什么影响？文档列了：对话的长度和复杂度、用了哪些功能、用的哪个模型、以及你选的 effort 档位。

这几项里，后两项最容易被低估。换个模型、调一档 effort，你什么都没多做，消耗变了。

说人话，effort 就是你让模型多想一会的那个开关。调到高档，它会自己拆步骤、自我检查、答完再回头验一遍，活干得更稳，也吃得更狠。你感觉只是「让它认真点」，账面上是一笔一笔往外走的。

你估不出来

所以「估不出来」这话听起来像夸张。它是这套机制的结构性后果。

按条数的时候，你的预算在心里：还剩二十条，省着点用。按 token 的时候，你只能去设置页看那根条掉了多少。而决定它掉多快的，一半在你手里（问多长、用多强），一半在你不太会去动的地方（模式、档位）。

我这大半年的体感是：撞墙我还忍得了。难受的是不知道墙在哪。

5 小时窗口反而好办，泡杯茶等一会儿就回来。难的是周限额，撞上了就是几天，你只能干看着，而且没有任何办法把它提前重置。

更别扭的是，周限额被撞上的时机跟你努力不努力关系不大。它取决于你这周赶上几个大任务。一个卡了三天的 bug，可能就是那根压垮的稻草。

现在 OpenAI 的用户要开始学这套了。

顺带说一句，四个月前完全另一套。7 月 OpenAI 拆的是 5 小时限速墙，我当时写过，重点在那个「暂时」。从按钟点卡你，到按用量跟你算账，卡人的办法换了。

我不劝你换

有人会说，既然 Claude 早就这样，OpenAI 也这样，有什么好讲的。

我想说的是另一件事：两种切法都不善良，区别在于把不确定性放在哪。

以前 OpenAI 把不确定性放在「你什么时候被限速」，Claude 把不确定性放在「你这周还剩多少」。12 月之后，两边的形状差不多了。

这件事再往深一层看，其实是 agent 把用量结构改了。我以前写过一句判断：一个 agent 跑几个小时的 token 消耗，是一年前手动打字的几十上百倍。手打的时候，用量跟你敲键盘的时间几乎成正比；现在你人走开了，它还在跑。订阅套餐是按「人在用」的强度设计的，碰上一个不睡觉的东西，账当然对不上。

对你真正有用的东西只有一件：提前知道自己会被哪一刀切到。

如果你手上同时有 ChatGPT 和 Claude 的订阅，这个月是个挺好的观察窗口。同一周的活，两边各掉多少，自己记两笔，比任何评测都准。记的时候别只记「用了多少」，记清楚当时用的哪个模型、开的哪档 effort，那两个才是真正吃额度的变量。

记满四周，你会得到一张只属于你自己的价目表：哪种活最贵、哪个模型最不划算、哪一档 effort 值得开。到那时候再回头看官方那句「大多数用户不会更频繁地等重置」，你就知道自己在不在那个「大多数」里面。

你现在按什么估自己还能用多久？是数消息条数，还是看设置页里那根条，还是干脆不算，撞上了再说？
