我盯 agent 的土办法，被 xAI 做成了产品

发表于 2026-09-04 更新于 2026-09-08 分类于 产品 阅读次数： 本文字数： 2.6k 阅读时长 ≈ 2 分钟
xAI 9月3日发布 Grok Bot 设计文章，把产品主对象从会话换成有记忆和云电脑的 Bot，用户研究显示人盯 agent 图的是安心而非过程数据，界面用状态、预览、接管三级访问替用户分担盯梢。

Hello，我是飞飞。

9 月 3 号 xAI 发了篇少见的文章。没有新模型，没有跑分表，讲的是他们怎么给 Grok Bot 这个 agent 产品做界面。我啃完全文，停在了他们用户研究的一句结论上：用户盯着 agent 干活时要更多过程细节，追问下去，动机基本是为了确认它还在正常干活。设计团队给这东西起了个词，安心。

这句话像面镜子。我盯了我那些后台 agent 大半年，回头一看，我做的事跟「审查」压根不沾边。

会话确实过期了

先补背景。Grok Bot 8 月 11 号开的 beta，每个 Bot 配一台云上的电脑，浏览器、文件、终端齐全。你派活，它自己干，干完或者卡住了回来找你。对外报价 $120 一个月（口径来自 VentureBeat），9 月 3 号又开了企业版，激活入口干脆摆在 cursor.com 上，跟 Cursor 捆绑的意思不用猜。

设计文章里最值得琢磨的，是选哪个东西当产品的主对象。眼下主流的 AI 产品，主对象全是会话。会话这东西的形状你是熟悉的：有问题，开一个；解决了，它沉下去；过一周再想找，你顶多翻翻最近五条。

xAI 的原话说，当对面的东西被期待认识你、记得之前的活、长期负责，会话当主对象就变得奇怪。所以 Grok Bot 的主对象是 Bot：有名字，有头像，有头衔，记得跟你的全部历史，有一台自己的电脑。你明天回来，面对的还是同一个它。

习惯了会话的人注意，这个调头不小。侧边栏从聊天记录变成了花名册，你雇的不再是一个问答窗口，是一排能一直干活的同事。

它的脸就是状态

Bot 一多，新问题跟着来了：一花名册的 Bot，我怎么一眼看出谁在干嘛。

xAI 的做法是把状态画在头像上。每个 Bot 有六种状态：闲着、在想、在干、在等、卡住、干完了，全靠头像动效表达。闲着时安静带点好奇，来活了先应一声，开干之后动起来，需要你拍板时换成另一种动作，干完归位。你早上派一圈活出门，中午扫一眼花名册就够：一个在动，一个卡着，一个干完了亮着等你收货。他们管这叫 presence，在场感。同事坐在工位上，你余光就知道他在不在，不需要他喊一嗓子。

我顺着这个思路往下想，发现他们真正解决的是个老问题：盯。盯着一个看不见的 agent，你分不清它是没动静还是在憋大招，是卡住了还是在等你。会话产品里你只能盯着转圈的小点点，那玩意儿传达不了任何信息，只有干等。

用户要的是安心

设计文章里我最想跟你聊的，是他们砍掉一个功能的过程。

他们试过在头像动效之外，显示一行文字，说清 Bot 当前在做哪一步。结果用户看到一步，就要剩下的全部。团队去追问为什么，答案出乎意料：用户要这些细节，主要是想确认它还在干活、没跑偏。研究里给这种需求起了个名字，reassurance，安心。

这个词戳破了我一个以为只有自己才有的习惯。我天天用 Claude Code，审 agent 的活靠三样：git diff 逐行过，测试跑没跑通，输出对不对。全是看结果。它中间怎么想的、为什么绕那条路，我一次都没回头审过。前几天我还在文章里认过这个账：我的审查体系里，压根没有过程这一栏。

我一直当这是我偷懒。xAI 的用户研究说的是另一件事：这是普遍情况。人不会真去审 agent 的过程，人要的是被安抚。

这跟家里装婴儿监视器是一回事。你不会整晚盯着屏幕逐帧看，你瞄一眼，孩子还在动，就回去睡你的。监控录像那种东西是事后查证用的，监视器是当下安神用的。你要的东西不一样，界面给的东西就该不一样。

界面的职责跟着变了。它不用把过程数据全堆给你，它要把「一切正常」这件事，用你扫一眼就懂的方式递过来。

盯它分了三级

Bot 那台云电脑给你看多少，xAI 的取舍更明显。

他们试了四种排布：浮动窗口、并排显示、弹窗、全屏。发现电脑露得越多，用户越像监工，时刻盯着不敢走开。最后定成三级：电脑活跃时标题栏图标变紫，这算吭一声；想细看，开个固定侧栏旁观，不用离开对话；真出事了，全屏接管，帮完再交还。壁纸还随昼夜变，给那台电脑一个独立的时间感。

原文里有句判断我抄在这：每删一个东西都问同一个问题，这是帮人委派，还是又给他一件要管的事。

我对照了一下自己的土办法。我用 Claude Code 的后台 agents，看板常年开着三个栏目：在跑、等你、干完了。空格键偷看一眼，回车钻进去接管，接管时它跑在单独的 worktree 里，弄不坏我的目录。名字是英文的，习惯是土的。跟那三级几乎是同一张图。差别在方向：我的看板是我主动去看，不开面板就两眼一抹黑；Grok Bot 是它主动表态，动效一直亮在那，余光扫一眼就够。

看板里最常亮的是「等你」那栏。我的写作流水线跑到要拍板的环节会自己停下，比如选题环节，五个候选摆好了，它就挂在那等我点。有回我上午派了活出门，下午回来开看板，三四个会话整整齐齐停在那，就差我一句话。那几次我才咂摸出味来：耽误事的哪里是它干活慢，是我压根不知道它在等我。要是那会儿有个动效一直亮着告诉我「卡住了，等你」，我起码能早三个钟头回来收活。Grok Bot 把「在等」单列成一种状态、画在脸上，冲的就是这个场景。

顺带说，它把记忆归到 Bot 本人名下、工具放账号层共享，定时任务也搬进了 Bot 的主界面，跑过什么在对话流里留痕。我那间服务器上住着的 Hermes 室友，是这套东西的土制版。这层取舍等我真用上再细说，先回到盯这条线上。

先泼两盆冷水

夸完了，冷水也得泼，两盆。

一盆浇在安全上，说实话这条是我看完全文最在意的。外面把口径对齐过的报道说，同一个账号下所有 Bot 共用同一台云电脑，文件、浏览器会话、命令行凭证互相都摸得到，xAI 自己都提醒别把不同的 Bot 当安全边界。凭证怎么存的，能不能给单个 Bot 只开部分权限，没见细说。这跟我这个月一直在写的权限系列是同一条线：界面上给你三级门禁，底下的电脑还是一台，agent 手里的钥匙只会越配越多。

另一盆浇在成色上：没有独立定价，捆在套餐里当赠品，这类东西得拿真活试过才算数。官方说数千个组织在用、大头根本不在写代码上。这些我都没实测过，你当方向看。我最重的活都压在 Claude Code 的 skill 流水线上，搬家的账之前算过，不轻。

所以那块我盯了半年的后台 agents 看板，暂时还退休不了。但我打算把「替我分担盯梢」记成一把新尺子，下次再有 agent 产品发布，先量量它站在哪一级，别光看它多能干。

轮到你了。你的后台 agent 是怎么盯的，攒了自己的看板，还是干脆干等它回来交活？评论区聊聊，我想看看大家都卡在哪一级。
