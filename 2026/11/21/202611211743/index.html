26B跑进32GB的Mac，靠的是同一批层跑三遍

发表于 2026-11-21 更新于 2026-11-28 分类于 AI 阅读次数： 本文字数： 2.9k 阅读时长 ≈ 3 分钟
Inkling 2 Mini用26.4B总参约20GB体积跑进32GB内存的Mac，靠原生4bit与循环层把24层权重跑出48层计算，存储买深度时间付账；官方自认中文输出生硬、agent可能不确认就删文件，本地分界线暂不动。

Hello，我是飞飞。

9 月 20 日我写过阶跃那个 600B 的开源模型，结尾留了一句话：看看这堵墙有没有松动的迹象。到时候成不成，我另写一篇交代。今天来交代：墙没松动，600B 级依旧搬不动。松动的是墙这边能买到的能力。

你要是也用 Mac，也动过在本地跑大模型的念头，这条新闻就跟你有关。Thinking Machines 发布了 Inkling 2 Mini。26.4B 总参数，权重文件约 20GB，官方说 32GB 内存的 Mac 用 Ollama 就能跑。

Apache 2.0 协议，1M 上下文，一次能吞百万 token 的料，一个中型代码仓库整个塞进去都装得下，还能读图。

四月我跑不动26B

4 月我想在我那台 MacBook Pro 上跑 gemma4 的 26B 版本，撑不住，退到 e4b，有效参数 4.5B。Ollama 接上 Claude Code，每秒 20 到 40 个 token。

印象最深的坑是兜圈子。写输入校验那段，它突然停住。我等了 40 秒，它从头再输出一遍，全是已经写过的函数。上下文一长，小模型就容易找不到方向。我把上下文配到 32768，温度降到 0.8，它老实多了，但除不了根。后来把任务拆小，每次只让它做一件事，它稳定下来，写出一个约 60 行的计算器。

还有一次在高铁上，我想用 Claude Code 处理点东西，没信号，直接废掉。我才意识到自己对云端有多依赖：它断了，工作也断了。本地模型的一个真实价值也就在这：它不会在你最需要的时候突然断网。速度上它确实吃亏，复杂任务容易卡壳，调试也麻烦，出了问题你分不清是模型能力不够，还是参数没配对。

那篇结尾我画了条分界线：实验、学习、小任务给本地；需要真正写好代码的复杂任务，切云端。

这次动笔前，我让 AI 查了下这台机器：M1 Pro，32GB 内存，恰好踩在 Inkling 官方最低门槛上。说清楚，我没跑过 Inkling。

磁盘只剩 50GB，20GB 的权重文件一放，四成剩余空间就没了。Ollama 客户端偏旧，循环模型的本地运行时支持又刚出来，升级折腾一圈时间成本不低。这篇只谈官方和第三方口径。

同样 26B 级，这次凭什么塞得进去？

26B怎么塞进20GB

能塞进去，是三层机制叠出来的。

MoE 是 9 月的旧话。26.4B 总参数，每个 token 只激活 3.4B。MoE 说人话就是模型里养着一堆专家，每次计算只叫醒几个。但稀疏省的是计算，存储一分不省。26.4B 是图书馆的全部馆藏，3.4B 是你一次借阅的量，借得少，书架照样得把整个馆藏放下。

原生 4bit 把存储压下来。常见权重用 16 位浮点数存，NVFP4 格式用 4 位存一个，体积直接缩到四分之一。关键是它打训练起就用 4bit，部署也是 4bit，没有训练完再压缩那道工序，也就没有事后压缩带来的精度损失。24 层里 20 层用 NVFP4，末 4 层用精度稍高的 MXFP8。约 20GB 的体积，是这一层挣来的。

循环 Transformer 是最有意思的一层。它只存 24 层权重，但首尾 12 层各跑一遍，中间 12 层每个 token 要跑 3 遍，加起来 48 次层计算。每 token 有效激活 5.4B，比规格表上那个 3.4B 高出一截。

循环发生在推理的时候。接着图书馆的比方说：馆藏没变，同一批书被反复借阅，每本书翻三遍，读出来的理解就比翻一遍深。深度是跑出来的。

存储买深度，时间付账。

这招值不值？官方做过对比：一个不循环的模型，要追平它自主干活（agentic）的表现，得多花 140% 的推理算力。复用层是真能折价买到能力的。官方给的编码基准 SWE-bench Verified 成绩是 79.2%，编码这块确实进了第一梯队。

循环这个想法本身也不新，2018 年就有 Universal Transformers 这篇论文，新的是把它训到能用的工程。

官方自己认的短板

模型卡里把局限逐条列了出来，有两条，中文开发者首当其冲。

中文输出措辞生硬，还会混杂语言。对天天用中文干活的人，这不算小瑕疵：输出要进文档、进注释、进给同事看的说明，每段都得人工再过一遍，省下的 API 钱又变成了校对时间。

agent 场景里，它可能不经确认就删除或覆写文件，也可能陷入重复推理循环。官方自己给的建议是限 token、限轮数，再加沙箱。沙箱说白了就是一个隔离环境，它碰不到外面真实的文件。

重复推理循环的危害也很实际：模型卡死在循环里的时候，token 在烧，轮数在涨，任务一步没动，没人盯着的话，可能空转很久才被发现。

看到这条我想起 4 月 gemma4 兜圈子。不同的模型，不同的成因，症状却一样：你以为它在干活，它其实在原地打转。我那套拆任务的土办法，跟官方限轮数的建议算是撞上了。

知识边界也认了。循环加的是推理，加不了知识。一项叫非幻觉率的测试，分越高越少胡说：它 63.4%，Qwen3.8-27B 71.4%。幻觉就是一本正经地胡说，官方承认它比大模型更爱自信地说错。给的补法是搜索和工具：知识不够，就让它在干活时现查，别指望权重里背下了所有答案。

推理还关不掉。effort（思考力度）开到最低，它也要先想一遍。每个 token 烧的算力，比你看着 3.4B 激活参数猜的要高。

时间这份账怎么算

第三方评测机构 Artificial Analysis 给了一组 API 口径的数字。

智能指数上 Inkling 2 Mini 平了 Qwen3.8-27B，但同分之下，它输出的 token 多 38%。

每任务它 0.59 美元、9 分钟就干完，Qwen3.8-27B 要花 3.53 美元、38.2 分钟。别读成它更慢，钱和时间它都花得更少。

时间换的是深度：同样的能力，不循环的架构要多付算力，前面那 140% 就是标价。

这份账在云端是钱，到了你的本地机器上就变成等待。agent 任务一跑几十轮，每轮多吐一截 token，屏幕上光标闪的时间就拉长一截。官方那张速度图给的是理论上限，没给实测。最低门槛的机器上到底跑多快，眼下没人说得准，我也没法替它打包票。

分界线暂时不动

先把它跟闭源的摆一起：GPT-6 Luna 在同一指数上拿 28 分，每任务 0.15 美元，更聪明也更便宜。Inkling 的赢面在开放权重、离线可用、能拿自己的数据接着训。这份自由，闭源 API 给不了。

中文输出和 agent 可靠性这两条官方短板，都正对着我天天用中文指挥 AI 干活的日常。让它进仓库干活，不经确认删文件这个风险，我眼下不敢接。所以 4 月那条分界线，这次的判断是暂时不动。

但墙的性质变了。4 月那堵墙叫跑不动，硬件直接关门；现在这堵墙叫知道代价，门开着，进不进是你自己算账。

想试的人，我的建议是沙箱装好，轮数限住，中文输出自己验一遍再信。好在它的思考过程压缩过也读得懂，它怎么想的，你能盯着看。

分界线什么时候会动？我在等两个信号：中文输出的口碑起来，agent 可靠性被第三方反复验过。这两条松一条，这条分界线就该重新算了。

官方演示里，一台 M5 Pro 48GB 的 MacBook 开着飞行模式，离线搭出了一个飞行模拟器。飞机上没网也能干活，这件事从演示视频变成了可以下载到自己机器上的东西。

9 月的伏笔今天兑现一半：600B 依旧搬不动，26B 级却把自主干活的编码能力带到了笔记本上。本地模型的下一步是复用层，不是砍参数。

你的 Mac 内存多大？要是给这个 26B 一次机会，你打算让它在沙箱里先干哪件活？评论区聊聊。
