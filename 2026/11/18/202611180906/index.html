Claude 不再一个个调工具：一段脚本替掉一串来回

发表于 2026-11-18 更新于 2026-11-19 分类于 AI 阅读次数： 本文字数： 3.5k 阅读时长 ≈ 3 分钟
Claude Code 实验性 Code Mode 让模型写一段 JavaScript 连续调工具，把多次往返压成一次编排。工具调用的瓶颈从模型转向编排，代价是审查颗粒度变粗，v2.1.323 起还要过一长串环境门槛。

Hello，我是飞飞。

如果你用 Claude Code 跑过多步任务，下面这个场面应该很熟：让它查个东西、改个文件、再跑一遍测试，工具调用一条接一条往上滚，每一条后面都跟着一次等待。你盯着它滚，它盯着结果，中间隔着一来一回。

Claude Devs 昨天发了条推文，Code Mode 上线，实验性的。它要砍的就是这个「一来一回」。我还没开过它，这里讲的是官方文档里的机制。

一次工具调用要几个来回

没有 Code Mode 的时候，Claude 要读一个文件，就发起一次 Read。结果回来，它看完，再决定下一步是改还是继续读。要跑命令，就发起 Bash，等命令结束，拿到输出，再想下一步。

每一步都要走一个完整的回合：模型先说要调什么，工具执行，结果回到模型，模型再决定。官方文档写得很直白，模型会「直接请求 Bash、Read、Edit 这样的工具调用，并且在决定下一步之前读每一个结果」。

你让它改一个变量，它得先搜、再读、再改、再跑测试。四次举手，四次等回话。四步加起来，能听见风扇响。

还有一笔成本容易被忽略。工具吐出来的东西，不管有用没用，通常都要先进上下文。一次目录列表几百行，一次测试输出几千行，模型为了判断下一步，得先把它们读一遍。真正需要的可能只是其中一行。

回合本身也占时间。模型每次决定下一步，都要带着前面的全部记录重新想一遍。工具调用越密，这种重复读的量越大。你以为慢在模型想得不够快，其实慢在它一遍遍把同一堆东西重新看。

它改成先写一段脚本

Code Mode 换了做法。

Claude 不再一次要一个工具，它写一段 JavaScript，由 Claude Code 在你的会话里执行。这段代码可以并行跑几条命令，可以把上一步的结果直接喂给下一步，也可以只把模型真正要看的那一小段返回。

跑代码的是一个新的工具，叫 REPL。你在对话里看到的还是工具调用，比如那次改动产生的 diff，代码本身是折叠起来的。按 Ctrl+O 打开记录，才能看到每一段 JavaScript。

这跟写一个 skill 不是一回事。skill 是写给模型看的手册，模型照着做，每一步还是要回到模型那里确认。Code Mode 里的脚本是写给机器执行的，模型只在写完和跑完之后各看一次。中间的判断被搬进了代码。

省下的是等和搬运

原来的循环里，模型大部分时间干两件事：等工具回话，把结果搬进上下文。

写脚本把这两件事挪进了代码。循环次数少了，搬进上下文的中间结果也少了。模型只在脚本跑完后看一次它真正需要的东西。

工具名没变，Bash 还是 Bash，Read 还是 Read。挪位的是决定权：先调哪个、结果怎么接，从模型手里进了代码。

我前几天写过一篇讲 Claude Code 的 exit 2，说质检脚本能替人喊停。这次官方动的是另一头：把一串调用压成一次编排。

这两件事其实是一套思路的两面。检查靠脚本，调用也靠脚本，模型负责的部分越来越像「写清楚要什么」和「看跑完的结果」。

审查的那双眼变粗了

省下来的东西有代价，而且这个代价不小。

Code Mode 里，代码里的每一次工具调用，照样要过你的拒绝规则、询问规则和 PreToolUse hook，用的还是 Bash、Read 这些原来的工具名。说人话就是，动手前先过的那道检查脚本，这一层没变。

变的是自动模式。原来的自动模式是逐个工具调用让分类器审，现在变成审这一整段代码。文档里特意提醒了一句：分类器看不到运行时才算出来的值，比如从搜索结果里取出来的那个路径。你写的规则如果只按命令文字匹配，脚本完全可能拼出一条规则没覆盖到的命令。

还有个更具体的坑。文档说，在 Code Mode 里，cd 'app' && git push 这种复合命令，可能以整条的形式送到你的 hook 面前。以前你按 git push 写规则，现在得考虑前面挂着 cd 的情况。

想审代码本身，得写一个匹配 REPL 的 PreToolUse hook，从 tool_input.code 里把那段 JavaScript 读出来。也就是说，审查的颗粒度从「每一次动作」变成了「一段程序」，要管得更细，得自己补工具。

这么设计也不算没道理。逐条审调用，你能准确知道它碰了什么。审一段代码，你拿到的是意图，细节藏在代码怎么跑上。换我设计，大概也会先用这种方式把功能放出来。

它值得写，但不该一上来就开。它能省的是等待，放大的是「你以为规则管住了，其实管住的是另一层」这种错觉。放权的口子换了个形状，守门的人也得多学一种看法。

门槛比想象的长

我把文档里的要求从头看到尾，感觉这张清单比一个开关难跨多了。

版本要到 v2.1.323 以上。账号得是 Claude 订阅或者 Console。走网关、Amazon Bedrock、Google Cloud、Microsoft Foundry 这些渠道的都不行。官方排查表里还点名了自定义 ANTHROPIC_BASE_URL 的接法。模型得是 Opus 5.5、Sonnet 5.5、Haiku 5.5 或 Fable 5.2。

形态也有限制。只能在终端里开交互会话，-p、Agent SDK、VS Code 面板、桌面端、云端会话都不支持。安装得用原生版本。组织开了 HIPAA 或者零数据保留的，也用不了。

开起来之后还有一串：会话只能在开着 Code Mode 的情况下恢复；不能转到桌面端，也不能转成后台会话；Remote Control、Claude in Chrome、computer use 这几个功能在 Code Mode 里不可用。代码如果在等，默认最多等十分钟；想让它后台跑，得从自动模式或者 bypassPermissions 模式启动，最长两小时。

这串限制里，最影响日常的是账号和形态。很多人的 Claude Code 接在中转或者云厂商上，按文档这条最先过不去。能在终端里开的，还得接受「这个会话以后只能带着开关恢复」这件事。

我的流水线最缺这个

我那条写公众号的流水线更夸张。一串环节接力：调研、写稿、润色、评阅、配图、分发，前面还有一个 director 负责编排。每一次交接，模型都要带着前面的全部材料再想一遍，等上一个工具把结果吐完。

所以我看到 Code Mode 的第一反应，是它能少几次交接。token 省多少，反倒排在后面。我早就把能写成脚本的判断挪进去了：字数够不够、description 超没超、H2 有没有括号，现在都是脚本在查，不让模型肉眼数。Code Mode 让我看到的，是同一件事再往前一步：检查可以脚本化，调用也可以。

上线第二天，我这个会话也不在它支持的环境里。等我把手头这条流水线挪到一个能开的环境里，跑一遍同样的活，再来补一篇带数字的。

什么时候值得开

记一条就够：工具调用密集、彼此有关联的任务，值得试。

官方点了三种场景：一个改动要在很多文件里重复；一次搜索的结果要先过滤再给模型看；几条互不依赖的命令可以同时跑。

反过来，一次性的单步操作，开它没多少收益，还多背一层环境限制。

真要试，我建议先从只读任务开始。比如让它扫一遍某个目录，把结果筛完再回来。这类活不碰写权限，脚本写错了，损失也就是一次白跑。等你对「它会把什么塞进脚本」有感觉了，再往改文件、跑测试这种会留下痕迹的活上放。

还有个细节别忽略：代码跑起来的时候，权限提示可能夹在中间。默认等待模式会把停在提示上的时间也算进那十分钟。跑长任务前，先想清楚自己是要盯着，还是让它后台跑。

以前我们看 agent 干活，看的是它一条条地要工具，像一个人不停举手问「下一步呢」。Code Mode 想做的，是让它先把这一串问题自己在纸上算完，只把那张纸递给你。

省下来的回合是真的，审查变粗也是真的。这两件事同时成立，才是这个实验功能现在的样子。

你手上那条 agent 任务，一天里有多少时间是在等上一个工具回话？评论区说说，我看看是不是只有我这么盯着屏幕。
